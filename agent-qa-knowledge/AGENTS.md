# agent-qa knowledge — for coding agents

Generated by agent-qa init when it creates the workspace.

This folder holds what agent-qa learned from test runs and the QA policies people wrote.
Read it through agent-qa's commands, never through SQLite or index files.

## What's here
- `memory/<product>/bundles/<id>/` — one learned record per bundle: `record.md` and its evidence.
- `policies/` — QA rules people wrote; the runner applies them on every run.
- `memory/index/`, `memory/queue/`, `.lease`, `.epoch` and any SQLite file are generated
  runtime state. Never read or edit them.

Answer questions with the commands below: trust, validity and supersession are worked out
when you ask, so a raw `record.md` can be stale or superseded. Opening a bundle to look
around is fine.

## Questions → commands
| Question | CLI (add `--json` for JSON) | MCP tool |
|---|---|---|
| What happened in a run, and where is everything it recorded? | `npx agent-qa runs overview <runId>` | `agent_qa_get_run_overview` |
| Which runs exist, newest first? | `npx agent-qa runs list` | `agent_qa_list_runs` |
| One step's console, network, a11y, aria or variables | `npx agent-qa runs evidence <runId> --test <n> --step <n> --kind <kind>` | `agent_qa_get_run_evidence` |
| What knowledge did a run use and learn? | `npx agent-qa runs knowledge <runId>` | `agent_qa_get_run_knowledge` |
| Why did a step's brief say what it said? | `npx agent-qa knowledge brief-why <runId> --step <n>` | `agent_qa_explain_brief` |
| One record, with its provenance | `npx agent-qa knowledge show <recordId>` | `agent_qa_show_knowledge_record` |
| Which knowledge bundles exist? | `npx agent-qa knowledge bundles` | `agent_qa_list_knowledge_bundles` |
| Records by product, kind or scope | `npx agent-qa knowledge inspect` | `agent_qa_inspect_knowledge_records` |
| What changed since a build? | `npx agent-qa knowledge diff <build>` | `agent_qa_diff_knowledge_records` |
| Which marks and approvals back a record, and would it promote? | `npx agent-qa knowledge gates <recordId>` | `agent_qa_list_knowledge_gates` |

With `--json` each verb prints what its MCP tool answers; `npx agent-qa knowledge inspect` and
`npx agent-qa knowledge diff <build>` (`<build>` is a build ordinal or tag) print only the `records` and `changes` array of that answer.

Test and step numbers are zero-based, as `runs overview` prints them. A screenshot:
`npx agent-qa runs evidence <runId> --screenshot <sha> --out <file>`.

## Provenance
Every record names where it came from: the runs and steps that taught it and the outcomes
its trust rests on. `knowledge show` returns them; cite the record id when you rely on one.

## Changing knowledge
Never edit files under agent-qa-knowledge/ yourself; knowledge changes only through agent-qa.
`agent_qa_change_knowledge` accepts, rejects or forgets a record, and the change applies at once.
Wrong knowledge is corrected by new feedback (a run mark) or by forgetting the record.

The `agent-qa-knowledge` skill has the workflow, with the depth in its references/ folder;
`npx agent-qa init` installs it in `.claude/skills` and `.agents/skills`.
